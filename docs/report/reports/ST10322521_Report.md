Booking endpoint rate-limit enforcement

**Method:**
An authenticated POST /api/bookings request was repeatedly sent through Burp Suite Repeater using a valid client JWT.

**Endpoint:**
POST /api/bookings

**Attack/Test:**
The same authenticated booking request was repeatedly sent until the configured request limit was reached.

A valid-format but nonexistent gig ID was used:

"gig": "000000000000000000000000"

This ensured that the requests could exercise the rate limiter without creating actual bookings or transactions.

**Expected:**
The first 10 requests should be processed normally, while subsequent requests from the same client/IP should be rejected with HTTP 429 Too Many Requests and the configured RATE_LIMIT_EXCEEDED response.

**Actual:**
The requests before the limit returned HTTP 404 Not Found with:

{"error":{"code":"NOT_FOUND","message":"Gig not found"}}

This confirmed that they passed through the rate limiter and reached the booking logic.

After the configured limit was reached, the next request returned:

HTTP 429 Too Many Requests

The response included:

RateLimit: "10-in-15min"; r=0; t=808

RateLimit-Policy: "10-in-15min"; q=10; w=900

Retry-After: 808

The API returned:

{"error":{"code":"RATE_LIMIT_EXCEEDED","message":"Too many booking requests. Please try again later."}}

**Result:**
PASS

**Evidence:**
Burp Suite Repeater response showing HTTP 429 Too Many Requests, RateLimit: "10-in-15min"; r=0, the 10-in-15min rate-limit policy, Retry-After: 808, and the RATE_LIMIT_EXCEEDED response.

**TEST KAN03-NPM-AUDIT-001**

**Name:**  
NPM dependency vulnerability audit and remediation

**Objective:**  
Identify known security vulnerabilities in the HustleHub+ backend dependencies and verify that vulnerable dependency versions can be updated without introducing breaking changes to the application.

**Method:**  
NPM dependency inspection and update performed against the local HustleHub+ backend.

The installed dependency versions and `package-lock.json` were inspected before remediation. The affected `braces` and `brace-expansion` dependencies were then updated using NPM.

**Endpoint:**  
Backend dependency environment; no API endpoint was directly tested.

**Attack/Test:**  
The project's `package.json`, installed dependency tree, and `package-lock.json` were inspected to identify the versions of `nodemon`, `chokidar`, `braces`, and `brace-expansion`.

The project was found to use `nodemon` version `3.1.14`, with the dependency tree containing `braces` version `3.0.3` and `brace-expansion` version `5.0.9`.

The `braces` and `brace-expansion` dependencies were then updated using:

`npm update braces brace-expansion`

NPM successfully updated one package and re-audited the project's 134 packages.

**Expected:**  
Known vulnerable dependencies should be updated to secure compatible versions.

The dependency update should complete successfully and the resulting dependency tree should remain installable.

NPM audit should report no remaining known vulnerabilities where possible.

**Actual:**  
The dependency inspection confirmed:

- `nodemon@3.1.14`
- `chokidar@3.6.0`
- `braces@3.0.3`
- `brace-expansion@5.0.9`

The dependency update completed successfully.

NPM reported:

`changed 1 package, and audited 134 packages`

The update did not report an installation failure.

However, after the update, NPM audit still reported **3 high-severity vulnerabilities**.

NPM indicated that resolving all remaining issues would require:

`npm audit fix --force`

which may introduce breaking changes.

NPM also reported that the `bcrypt@6.0.0` install script was blocked because it was not covered by the configured `allowScripts` policy. This was reported as an installation-script warning rather than a failed dependency update.

**Result:**  
PARTIAL PASS

The identified dependency update was successfully performed, but the overall vulnerability audit did not achieve a clean result because 3 high-severity vulnerabilities remained.

The remaining vulnerabilities were not automatically resolved using `npm audit fix --force` because that operation may introduce breaking dependency changes.
